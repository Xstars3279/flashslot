## 设计目标

可部署的 Java 后端实习项目，聚焦单台实验设备的分时预约。用户有充足时间，希望理解并参与数据库设计，重点研究并发正确性、幂等和故障恢复。

## 已确认决定

- 一条资源记录代表一台可独立预约的设备，同一时间最多一个有效占用。
- 预约主链路采用 MySQL 设备日期行锁，不采用 synchronized 或 Redisson 作为主要互斥机制。
- 保留 30 分钟时间格；对用户仍展示完整起止时间。
- 设备时间格占用的联合主键为 resource_id、book_date、slot_index，数据库禁止同一组合重复。
- 订单与占用分开：订单描述业务，占用记录提供单格归属和唯一性约束。
- 后端可以用 List 生成格子，以普通 INSERT 的多行 VALUES 批量写入；不把全部格子存成单一 JSON/字符串以替代占用明细。
- 订单创建、多格占用和必要的其他业务更新同事务提交；任意格冲突整体回滚，不使用 INSERT IGNORE 掩盖冲突。
- 固定每次两小时尚未采用；继续按现有可变时长、半小时对齐方案讨论。
- 用户已明确禁止同一人跨设备预约重叠时段，采用 user_slot_occupation 联合主键约束。

## 已确认并生成 SQL：设备与开放日历

- resource：设备身份、名称、所在位置、状态、默认开放范围、管理修改版本及时间。
- resource_day：设备某一天的开放范围、是否开放、排期版本与时间；联合主键提供可提前生成的行锁目标。
- 第一版按设备位置文本、统一管理员管理设计，暂不加入独立实验室表或分类字段。
- 用户确认第一版每天一个连续开放区间，不加入分段开放时段表。
- 设备默认开放规则更新只影响新生成日历；已有日历修改走独立接口并检查预约影响。
